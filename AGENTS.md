# AGENTS.md

This file provides guidance to agents when working with code in this repository.

## Stack
React 19 + TypeScript 6 + Vite 8 + Tailwind CSS v4 (via `@tailwindcss/vite` plugin — no `tailwind.config.js`, config lives directly in CSS via `@import "tailwindcss"`). Linter: `oxlint` (not ESLint). No test framework. Backend: **Supabase** (Storage + PostgreSQL).

## Commands
```
npm install       # required after first clone — installs @supabase/supabase-js and all deps
npm run dev       # Vite dev server
npm run build     # tsc -b && vite build
npm run lint      # oxlint (no --fix flag in scripts)
npm run preview   # preview production build
```
No single-test command exists — there is no test framework in the project.

## Environment Variables (required)
Copy `.env.local.example` → `.env.local` and fill in your Supabase credentials:
```
NEXT_PUBLIC_SUPABASE_URL=https://your-project-id.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-public-key-here
```
Without these set, the app falls back to the legacy `public/audio/` manifest scan (local dev only).

## Supabase Setup (one-time)
1. Create a project at supabase.com
2. Run `supabase/schema.sql` in the SQL Editor
3. Create a **public** Storage bucket named `audio-files`
4. Fill `.env.local` with the project URL and anon key

## Audio Storage Architecture
All audio files live in Supabase Storage bucket `audio-files`:
- **Built-in/operator tracks** → `tracks` table rows with `is_built_in = true`; path: `<category>/<filename>`
- **User-uploaded tracks** → `tracks` table rows with `is_built_in = false`; uploaded via `supabaseStorageService.ts`
- **Legacy fallback** (no Supabase URL set): `FolderScannerService` falls back to fetching `/audio-manifest.json` from `public/audio/<category>/` (generated by the `audioManifestPlugin` in `vite.config.ts`)
- **Never use `import.meta.glob`** for audio files — the plugin exists to keep large MP3s out of Rollup's asset pipeline

## Remote Persistence
- **`storageService.ts`** coordinates all loading/saving via Supabase
- `loadPlaylistsAsync()`: fetches built-in tracks (Supabase or manifest fallback) + uploaded tracks + ordering from `tracks` and `playlist_state` tables
- `savePlaylists()`: **fire-and-forget** async — updates `playlist_order` in `tracks` and `current_index` in `playlist_state` without blocking UI
- `localStorage` is **no longer used** — all state is remote

## AudioEngine Singleton
`audioEngine` (exported from `src/services/audioEngine.ts`) is a module-level singleton. It enforces **zero audio overlap**: every `playTrack()` call starts with `emergencyStop()`. Never call `new AudioEngineService()` — always import the singleton.

Category-specific auto-fade timers baked into `playTrack()`:
- `point_intros` / `super_spike` / `monster_block` / `fire_ball` / `ace`: 9s play + 3s fade = 12s total
- `technical_timeouts`: 50s play + 10s fade = 60s total
- `awards`: loops infinitely (HTML5 `audio.loop = true`)
- `presentation` / `timeout_continuous`: no auto-fade

## PlaylistCategory Values (9 total)
`presentation` | `point_intros` | `technical_timeouts` | `super_spike` | `monster_block` | `fire_ball` | `ace` | `timeout_continuous` | `awards`

When adding a new category, update all **five** locations: `src/types/audio.ts`, `storageService.ts` (`INITIAL_PLAYLISTS`), `audioEngine.ts` (`categoryDurations` + `jingleActive` + auto-fade block), `folderScannerService.ts` (`validCategories` + `durationMap`), and `supabase/schema.sql` (`playlist_state` seed).

## TypeScript Config (Non-obvious)
`tsconfig.app.json` enables `verbatimModuleSyntax` — **always use `import type` for type-only imports**. Also enforces `noUnusedLocals` and `noUnusedParameters` which are errors at build time (`tsc -b` runs before Vite).

## Code Style
- Named exports for components and hooks; default export only added as an alias at the bottom of the file (`export default App`).
- Singleton services export a pre-constructed instance alongside the class.
- `useRef` pattern for stable callbacks in hooks (see `useHotkeys.ts`, `useAudioPlayer.ts`).
- Tailwind utility classes only — no CSS Modules. Custom animations/keyframes in `src/index.css`.
- `clsx` + `tailwind-merge` available as utilities for conditional class merging.
